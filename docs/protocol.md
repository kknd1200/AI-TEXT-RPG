# ENS 프로토콜 명세

배틀몬스터3 / Monster3K (`com.ensony.battlemonster3`) 클라이언트가 쓰는
온라인 프로토콜입니다. APK 안의 `lib/*/libjccvt.so` 를 역분석해서 복원했고,
근거가 되는 함수 주소는 `armeabi-v7a` 기준입니다.
`python3 tools/extract_protocol.py libjccvt.so` 로 언제든 재생성해서
이 문서와 대조할 수 있습니다.

## 1. 접속 정보

| 항목 | 값 | 근거 |
|---|---|---|
| 전송 | TCP (`socket(AF_INET, SOCK_STREAM, 0)`) | `MC_netSocket` @0x1bf20 |
| 원 서버 주소 | `218.50.3.88` | `EFC_netSET` @0x1de80 의 문자열 상수 |
| 포트 | `0x139a` = **5018** | `MC_utilHtons(0x139a)` in `EFC_netSET` |
| 수신 버퍼 | 2048 바이트 | `EFC_netALLOC(0x800)` in `EFC_netREQUEST` |

주소는 문자열을 `inet_addr()` 에 넘겨서 구합니다(`MC_utilInetAddrInt` @0x1bd10).
즉 **도메인 이름은 못 씁니다.** 반드시 IPv4 주소여야 합니다.
서버를 바꾸는 방법은 [setup.md](setup.md) 참고.

## 2. 요청 패킷 (클라이언트 → 서버)

`Net_SetPACKET1` @0x34370 이 만드는 47바이트 헤더 + 페이로드입니다.
모든 정수는 **리틀 엔디안**입니다 (`EFC_fsWriteUint16` @0x1c9a4).

```
오프셋  크기  내용
  0      3   "ENS"
  3      3   통신사 태그. 명령 0x13 / 0x39 / 0x3a 는 "SKT", 나머지는 "KTF"
  6      1   0x11 (고정)
  7      2   0x0087 (고정)
  9      2   명령 ID
 11      2   본문 길이 = 34 + 페이로드 길이
 13     21   전화번호 (플레이어 식별자, NUL 패딩)
 34     10   단말 모델명 (NUL 패딩)
 44      3   "100" (클라이언트 버전)
 47      *   페이로드
```

길이 필드는 **자기 뒤에 오는 바이트 수**입니다. 헤더 뒷부분(21+10+3=34)에
페이로드 길이를 더한 값이고, 전체 패킷 크기는 `13 + 길이필드` 입니다.

### 식별자에 대하여

13번 오프셋의 21바이트가 이 게임의 계정입니다.
`EFC_mainInitialize` @0x2ca10 이 시스템 속성 `PHONENUMBER` 를 읽어서 채우고,
단말 모델명(`PHONEMODEL`)에 `Emulator` 가 들어 있으면 **`01123456789`**
로 강제합니다. 에뮬레이터에서 여러 명이 붙으면 전부 같은 계정이 되니
주의하세요 ([setup.md](setup.md) 의 "플레이어 식별자" 절 참고).

## 3. 응답 패킷 (서버 → 클라이언트)

`Net_dataRECEIVE` @0x33f80 이 파싱합니다.

```
오프셋  크기  내용
  0      3   "ENS"
  3      2   명령 ID (요청한 값을 그대로 돌려줌)
  5      2   본문 길이 = 2 + 페이로드 길이
  7      2   결과 코드
  9      *   페이로드
```

클라이언트는 수신 버퍼에서 `"ENS"` 를 **앞에서부터 스캔**하기 때문에
앞에 쓰레기 바이트가 있어도 복구합니다. 다만 길이 필드가 아직 도착하지 않은
바이트 수보다 크면 그 패킷은 통째로 버립니다.

### 결과 코드 (`Net_SetRECEIVE` @0x33588)

| 값 | 의미 |
|---|---|
| `0x0000` | 성공 |
| `0x8601` | 성공 (과금 모듈이 쓰는 별칭) |
| 그 외 | 실패. 클라이언트가 **페이로드를 읽지 않고 건너뜁니다** |

이 서버는 "보낼 목록이 없음"을 `0x0001` 로 알립니다. 빈 목록에 성공을
돌려주면 클라이언트가 없는 레코드를 읽어버리기 때문입니다.

### 목록형 응답

목록 화면의 파서(`Net_favorite_2RECEIVE`, `Net_unknown_log_2RECEIVE`,
`Net_battle_rank_3RECEIVE` …)는 **레코드를 딱 하나만** 읽고, 그 첫 바이트가
슬롯 번호(`u8`)입니다. 그래서 서버는 **행마다 응답 패킷을 하나씩** 보냅니다.

## 4. 명령 목록

`Net_*REQUEST` 함수가 `Net_SetPACKET1/2` 에 넘기는 ID입니다.
`id21` 은 21바이트 NUL 패딩 문자열(전화번호)을 뜻합니다.

### 세션 / 기타

| ID | 이름 | 요청 페이로드 | 응답 페이로드 |
|---|---|---|---|
| `0x13` | sms | 없음 | `u32` |
| `0x1e` | time | 없음 | `s32` 서버 시각. 클라이언트는 로컬 시각과의 차이를 저장 |
| `0x23` | user | 없음 (헤더의 식별자만 사용) | 없음 |
| `0x39` | cash_is_buy | 결제 조회 | — |
| `0x3a` | cash_buy | 결제 요청 | — |

`0x39`/`0x3a` 는 KT 올레마켓 결제 게이트웨이용입니다. 이 서버는 항상 거절합니다.

### 미지의 섬 (`Online_Unknown_*` 화면)

| ID | 이름 | 요청 페이로드 | 응답 페이로드 |
|---|---|---|---|
| `0x121` | island_enter | `id21` + `u32` | 없음 |
| `0x122` | island_count | `id21` | `u32` 인원수 |
| `0x123` | island_target | `id21` + `u32` 인덱스 + `u32` 종류 | `id21` + `s32`×4 + `char[8]` + `char[10]` + `char[10]` |
| `0x124` | island_update | `id21` + `char[8]` + `char[10]` + `char[10]` | 없음 |
| `0x125` | island_box | `id21` + `char[8]` | 없음 |
| `0x126` | island_log_write | `id21` + `u32` | 없음 |
| `0x127` | island_log_list | `id21` | (행마다) `u8` 슬롯 + `id21` + `s32`×4 |

`0x124` 가 **내 섬 상태를 서버에 올리는** 패킷이고 (`Online_Unknown_Target_mRun`),
`0x123` 이 **남의 섬을 조회하는** 패킷입니다
(`Online_Unknown_List_mKeyPressed`, `Online_Unknown_Target_mKeyPressed`,
`Online_Unknown_Favorite_mKeyPressed`, `Battle_Network_mRun`).
이 둘이 곧 "다른 사람이 보이는가"를 결정합니다.

`0x125` 는 필드의 상자 처리(`Field_Box_mRun`)에서 나갑니다.

`char[8]` / `char[10]` ×2 세 덩어리의 내부 의미는 아직 필드 단위로 쪼개지
않았습니다. 서버는 받은 그대로 저장했다가 그대로 돌려주므로
(`island.blob8` / `blob10a` / `blob10b`), 의미를 몰라도 플레이어끼리는
정상적으로 보입니다.

## 5. 아직 확실하지 않은 것

정직하게 적어 둡니다. 이 서버로 접속과 기본 동작은 되지만, 아래는
실제 단말로 한 번 돌려보면서 채워야 합니다.

- `0x123` / `0x124` 의 `char[8]`, `char[10]`×2 안쪽 필드 의미
  (지금은 통째로 보관·반환).
- `s32`×4 각각이 무엇인지 (레벨/점수/상태 중 하나로 보이나 미확정).
- 실패 시 클라이언트가 화면에 뿌리는 에러 코드 표
  (`Online_netDrawMessage` @0x4e381 을 더 읽어야 함).
- `0x116` 요청의 뒷부분 필드 순서 (`Net_battle_rank_4REQUEST` 는
  `s32` 7개 → `char[40]` 3개 → `id21` → `s32` 7개 → `u8` 로 보임).

서버를 `--record` 로 띄우면 오간 패킷이 전부 JSONL 로 남으니,
그걸 보고 위 표를 확정하면 됩니다.
